# Conversation reading windows

Opening a saved conversation requests one 60-message tail window. Earlier and later windows overlap by half a page so the timeline can retain a visible scroll anchor. Message bodies, citations and tool results remain bounded to 60 messages in the store; the timeline initially renders 30. Disclosure state is bounded to 120 messages and 64 disclosures per message and is cleared when changing vaults or conversations.

`GET /api/chat/conversations/{id}/window` accepts `cursor`, or `around` and an optional `branch_leaf`. Cursors bind the vault database, conversation, selected leaf, message ID and direction. SQL walks only parent/sequence metadata for that branch, and reads and decodes bodies only for the requested window. Version siblings use a covering index. The existing offset endpoint remains available with bounded body reads for older clients. Migration v23 adds indexes without changing messages or branch identities.

Full-text search continues to cover all saved attempts. An ID lookup loads a window around a hit. Selecting another answer is necessary only when the hit belongs to another branch, and is disabled during generation. Clearing search restores the original bounded snapshot, branch, disclosures and scroll position. Late responses are discarded after a newer window request, conversation or vault change. Streaming deltas stay in a separate live message while older windows are displayed.

Reading windows do not define model context. New frontend requests use `use_saved_history` and send only the current user turn. On send, Core reconstructs the complete selected parent chain from stored content and assistant reasoning, without decoding historical tool-result JSON. Legacy callers retain their explicit-message behavior. Normal sends, edits and regeneration verify `expected_branch_leaf` before any changes. One `BEGIN IMMEDIATE` transaction reads retry permissions and the exact parent, creates the user branch, reconstructs context and reserves the response. Context or reservation failures roll back all changes. An explicit root parent is distinct from appending to the current leaf. Concurrent branch changes return a reload-required conflict rather than silently using a different context.

After a stream completes, fails or is stopped, retry first reloads a window ending at the chosen message. This updates the active-leaf guard without losing an older retry target outside the latest page. Stopping or changing conversations during that read cancels the send. Regeneration reuses the saved user turn; retries still derive tool-write permissions from all saved sibling answers. A cancelled or delayed stream can persist its partial answer on its original parent without replacing a newer generation or selected branch. Concurrent desktop requests keep preparation and persistence in their own vault databases.

Synthetic 10,000-message tests record body rows, payload and timings without user data. The window service decodes 60 bodies for both initial loading and ID lookup. Full parent metadata traversal is still proportional to branch length; this change bounds body/JSON/network work rather than caching entire conversations.
