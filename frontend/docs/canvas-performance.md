# Canvas geometry and preview limits

Each immutable canvas document has one node ID/order index and a node-to-incident-edge index. Initial geometry uses two indexed endpoint lookups per edge. During a pointer gesture, only edges incident to moved or resized nodes are recalculated; returning to the original position restores cached geometry. Pointer events are merged into animation frames, and pointer-up flushes the final position before making one undoable change. Escape, cancellation and unmount discard queued movement.

Curve culling uses a conservative control-point bounding box with arrow and label padding. A curve crossing the viewport stays visible even if both endpoint nodes are outside. Selected edges and edges incident to selected nodes remain available. Memoized node and edge rendering retains native button activation, translated labels, selection, previews and conflict status.

Preview keys include vault ID, canonical target path and known content hash. Only new or changed visible targets are read; a tree change elsewhere produces no preview request. Desktop payloads are checked against known SHA-256 revisions before caching. Targets without a hash are treated as unverified and invalidated when their tree entry changes. Reads are coalesced, six run at a time, and stale vault/revision results cannot allocate an object URL or replace current content.

The cache holds at most 96 entries and 32 MiB of stored preview data. Markdown stores its short summary, not the complete document. Image object URLs belong to the cache and are revoked on replacement, eviction, vault change and unmount. Visible previews beyond the capacity show an explanatory message; zooming in releases unused cache entries. These limits describe stored text/blob data, not total decoded image or WebView memory.

The checked-in geometry fixture uses 2000 nodes and 4000 edges. Legacy endpoint searches read node identities 8,004,000 times; indexing reads 2000 identities and resolves 8000 endpoints. Ninety frames moving one node recalculate 360 geometries instead of 360,000. Preview regressions cover unrelated updates, shared targets, revision mismatch, movement/deletion, late reads, capacity and URL disposal.

On Windows 11 build 26100, WebView2 154.0.4258.48, the same synthetic canvas and 90-step drag measured a frame interval P95 of 80.1ms before optimization and 10.1ms after indexing, culling, frame merging and memoization. Frames over 50ms decreased from 43 to zero; 1064 nodes and 2130 relevant edges were rendered, compared with all 4000 edges before. JavaScript heap snapshots were 32.88/42.94 MiB before/after the baseline gesture and 25.39/39.69 MiB for the optimized gesture. These are one-machine snapshots rather than a memory-leak proof or a promise of the same frame rate elsewhere. The rendering measurements used isolated synthetic storage and a development Host/UI batch still labeled alpha2; full beta1 Core/package and installation acceptance are recorded separately during release verification.
